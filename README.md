# 공수 Discord Bot

매주·매일 반복 스케줄 알림과 이모지 반응 기반 역할 선택 봇입니다. Node.js 24.17 이상, TypeScript, discord.js 14, Node 내장 SQLite를 사용합니다.

## 실행

```sh
npm install
cp .env.example .env
```

`.env`를 설정합니다. 채널 ID는 Discord 개발자 모드를 켠 뒤 채널의 **ID 복사**로 얻습니다.

```dotenv
DISCORD_BOT_TOKEN=봇_토큰
SCHEDULE_ALERT_CHANNEL_ID=스케줄_알림_채널_ID
ROLE_EMOJI_CHANNEL_ID=역할_선택_채널_ID
```

두 채널은 같은 서버의 텍스트 채널 또는 공지 채널이어야 합니다. 서버 ID와 애플리케이션 ID는 별도 환경변수 없이 연결된 봇과 채널에서 알아냅니다.

```sh
# 개발 실행
npm run dev

# 빌드 후 실행
npm run build
npm start
```

봇이 시작되면 해당 서버에 명령어 8개를 등록하고 역할 안내 메시지를 준비합니다. 설정 변경이 없으면 재시작 시 기존 메시지와 반응을 그대로 사용합니다. 역할 목록이 비어 있어도 안내 메시지는 하나 생성합니다.

## Discord 설정

1. [Discord Developer Portal](https://discord.com/developers/applications)에서 애플리케이션과 봇을 만들고 토큰을 `.env`에 설정합니다.
2. 서버 설치 링크에 `bot`, `applications.commands` 스코프를 포함합니다.
3. 봇에 **역할 관리** 권한을 부여합니다. 역할 선택 채널에는 **채널 보기**, **메시지 보내기**, **메시지 기록 보기**, **반응 추가**, **메시지 관리** 권한이 필요합니다. 알림 채널에는 앞의 세 채널 권한이 필요합니다.
4. 서버 역할 설정에서 **봇의 가장 높은 역할을 부여할 대상 역할보다 위에** 배치합니다.
5. 알림 대상 역할의 멘션을 허용하거나, 알림 채널에서 봇에 **@everyone, @here 및 모든 역할 멘션** 권한을 부여합니다. 실제 발송은 선택한 역할 하나만 멘션하도록 제한합니다.

이 구현은 Message Content, Server Members 등의 privileged intent를 요구하지 않습니다. 대상 멤버를 개별 REST 요청으로 조회합니다. **메시지 관리** 권한은 삭제·변경된 이모지에 달린 사용자 반응을 정리하는 데 필요합니다. 봇에 관리자 권한이 있으면 포함됩니다.

## 스케줄 명령어

서버 소유자 또는 **서버 관리** 권한 보유자가 사용합니다. 모든 시간은 **Asia/Seoul** 기준이며 스케줄 하나에 요일 하나 또는 **매일**과 멘션 역할 하나를 설정합니다. 특정 요일은 매주, `매일`은 모든 요일에 지정한 시·분으로 반복합니다.

| 명령어 | 인자 | 동작 |
| --- | --- | --- |
| `/addschedule` | `day hour minute content role` | 추가 |
| `/lsschedule` | 없음 | 전체 목록 |
| `/modschedule` | `idx [day] [hour] [minute] [content] [role]` | 지정한 항목만 수정 |
| `/rmschedule` | `idx` | 삭제 |

- `day`: 일~토요일 또는 **매일**, `hour`: 0~23, `minute`: 0~59. 추가·수정 명령 모두 같은 선택 목록을 사용합니다.
- `content`: 공백만 있는 내용을 제외한 1~1900자. 내용에 다른 멘션을 넣어도 선택된 역할 외에는 알림을 보내지 않습니다.
- `idx`: 목록에 표시되는 고유 ID. 삭제 후 남은 항목의 ID가 바뀌지 않습니다.
- 모든 명령어 응답은 실행자에게만 표시됩니다.

예시:

```text
/addschedule day:월요일 hour:20 minute:30 content:오늘 공대 출발합니다 role:@공대원
/modschedule idx:1 hour:21
/lsschedule
[1] 월:21:30 - 오늘 공대 출발합니다 @공대원
/rmschedule idx:1
/addschedule day:매일 hour:21 minute:00 content:일일 숙제 확인하세요 role:@공대원
/lsschedule
[2] 매일:21:00 - 일일 숙제 확인하세요 @공대원
```

알림 채널에는 `내용`과 `@역할`을 전송합니다. 목록과 역할 안내에서는 실제 멘션 알림을 발생시키지 않습니다.

## 이모지·역할 명령어

추가·수정·삭제는 **서버 소유자만** 가능합니다. 관리자 권한만 있는 사용자는 변경할 수 없습니다. `/lsroleemoji`는 일반 유저도 사용할 수 있습니다.

| 명령어 | 인자 | 동작 |
| --- | --- | --- |
| `/addroleemoji` | `emoji role` | 이모지와 역할 연결 |
| `/lsroleemoji` | 없음 | `[idx] 이모지 @역할` 목록 |
| `/modroleemoji` | `idx [emoji] [role]` | 지정한 항목만 수정 |
| `/rmroleemoji` | `idx` | 연결 삭제 |

```text
/addroleemoji emoji:🎮 role:@게임
/addroleemoji emoji:📢 role:@공지
/modroleemoji idx:1 emoji:🕹️
/lsroleemoji
[1] 🕹️ @게임
[2] 📢 @공지
/rmroleemoji idx:2
```

- Unicode 이모지와 **현재 서버의** 커스텀 이모지를 지원합니다. 커스텀 이모지는 `<:name:ID>` 또는 `<a:name:ID>` 형식으로 입력합니다.
- 한 메시지에 최대 20개를 등록합니다. 이모지와 역할은 각각 중복 등록할 수 없습니다.
- 일반 유저가 안내 메시지에서 반응을 추가하면 역할을 부여하고, 반응을 취소하면 역할을 제거합니다. 다른 메시지, 등록되지 않은 이모지, 봇의 반응은 무시합니다.
- 목록이 변경되면 **기존 메시지의 본문을 수정**합니다. 메시지 ID와 변경 없는 이모지의 사용자 반응은 유지합니다. 새 이모지는 추가하고, 삭제되거나 연결 역할이 바뀐 이모지의 반응만 초기화합니다.
- 메시지 수정 요청에도 멘션 차단을 명시합니다. 최초 생성, 메시지 유실, 설정 채널 변경 시에만 새 메시지를 보내며 푸시·데스크톱 알림을 억제합니다. 새 메시지의 배지·읽지 않음 표시까지 제거하는 것은 아닙니다.
- 메시지 갱신과 역할 부여·제거를 같은 큐에서 처리합니다. 갱신 도중 들어온 이전 연결의 반응을 새 역할에 적용하지 않습니다. 연결이 바뀐 이모지는 갱신 완료 후 다시 선택하세요.
- 연결 삭제·변경 및 메시지 복구 시 **기존에 부여된 역할은 유지**됩니다. 같은 역할의 이모지가 초기화됐다면 해당 이모지를 눌렀다가 취소해 해제할 수 있습니다. 목록에서 빠진 역할은 관리자가 직접 제거합니다.
- 반응 취소는 해당 역할을 제거합니다. 같은 역할을 관리자가 직접 부여했는지는 구분하지 않습니다. 선택용 역할을 별도로 운영하는 것이 적합합니다.
- 안내 메시지 갱신에 실패하면 설정을 보존하고 반응 처리를 중단한 뒤 30초마다 **같은 메시지**에서 재시도합니다. 마지막으로 반영한 이모지·역할 연결도 저장하므로 재시작 후에도 변경된 반응만 정리합니다. 안내 메시지를 수동 삭제한 경우에는 새 메시지로 복구합니다.

## 저장 및 운영 동작

- 실행 디렉터리의 `data/bot.sqlite`에 스케줄, 발송 이력, 이모지 매핑, 안내 메시지 ID 및 마지막 반영 상태를 저장합니다. 프로젝트 루트에서 실행하고 `data/`를 영속 보관하세요.
- `매일`을 지원하지 않던 DB는 시작 시 자동 마이그레이션합니다. 기존 스케줄 ID, 삭제된 ID의 자동 증가 순서와 발송 이력을 보존하며, 매일 스케줄도 ID 하나로 관리합니다. 새 선택지는 빌드 후 봇을 재시작하면 명령어 등록 과정에서 반영됩니다.
- 이전 버전에서 업데이트하면 필요한 저장 테이블을 자동 생성합니다. 기존 안내가 정상 상태라면 메시지와 사용자 반응을 유지한 채 본문만 갱신합니다. 이전 갱신이 실패해 반영 상태를 알 수 없는 경우에는 그 메시지의 반응을 초기화해 복구합니다.
- **봇 프로세스 하나**를 계속 실행하는 구성을 전제로 합니다. 여러 인스턴스를 동시에 실행하면 역할 안내 메시지 관리가 충돌할 수 있습니다.
- 스케줄러는 15초마다 현재 한국 시간의 분에 해당하는 스케줄을 확인합니다. 초 단위의 정각 전송은 보장하지 않습니다.
- 같은 스케줄 ID와 같은 날짜·분은 DB에 실행 이력을 먼저 기록하여 한 번만 발송을 시도합니다. 발송 결과가 불확실한 네트워크 오류에서 중복 전송하지 않도록 실패 시 자동 재전송하지 않습니다. 실패는 서버 로그와 `schedule_runs`에 기록합니다.
- 발송 직전 프로세스가 종료되면 해당 알림이 누락될 수 있습니다. 봇 종료 중 지난 스케줄을 소급 발송하지 않습니다. 재시작 후 다음 실행 시각(매일 또는 지정 요일)부터 정상적으로 실행합니다.
- 재시작 후에는 기존 안내 메시지의 새 반응 이벤트를 처리합니다. **봇 종료 중 발생한 반응 변경은 소급 동기화하지 않습니다.** 필요한 경우 재시작 후 반응을 다시 조작하세요.
- 커스텀 이모지 삭제, 대상 역할 삭제, 권한 및 역할 순서 변경으로 Discord API 요청이 실패하면 로그에 기록합니다. 해당 설정이나 봇 권한을 수정해야 합니다.
- DB를 백업하려면 봇을 정상 종료한 다음 `data/`를 복사합니다. `.env`와 DB는 Git에 포함되지 않습니다.

## 검증 명령

```sh
npm run typecheck
npm test
npm run build
```

테스트는 SQLite 저장·마이그레이션, 매일·매주 반복, 날짜·요일 경계, 중복 발송 방지, 명령 권한, 역할 안내 수정·복구, 기존 반응 보존, 반응 처리 순서 및 알림 차단 옵션을 대상으로 하며 실제 Discord에 접속하지 않습니다.

실서버에서는 스케줄 발송·멘션, 소유자가 아닌 사용자의 역할 설정 거부, 반응 추가·취소, 재시작 후 기존 메시지 반응을 확인하면 됩니다. 목록 변경 시 메시지 ID와 변경 없는 반응이 유지되는지, 반복 알림이 발생하지 않는지, 변경된 반응만 초기화되는지도 확인하세요.

## 구조

```text
src/
  index.ts       # Discord 연결 및 생명주기
  config.ts      # 환경변수
  commands.ts    # 슬래시 명령 등록·권한·처리
  discord.ts     # Discord API 및 권한 확인
  domain.ts      # 입력 검증·이모지·시간·출력 형식
  store.ts       # SQLite 저장
  scheduler.ts   # 매주·매일 반복 스케줄 실행
  roles.ts       # 안내 메시지 및 반응 직렬 처리
tests/
  bot.test.ts
```
